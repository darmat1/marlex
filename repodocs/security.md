# security.md — правила безопасности

<!-- Purpose: the agent never trades security for "just make it work". -->

## Секреты
- Единственный источник секретов — переменные окружения (`.env` локально, Vercel project env vars в проде). `.env` в `.gitignore`, не коммитится.
- `BETTER_AUTH_SECRET` — обязателен, без запасного значения в коде (см. [[decisions#ADR-004]]); отсутствие переменной должно приводить к явной ошибке при старте, не к тихому fallback.
- BYOK API-ключи AI-провайдеров, которые вводит пользователь, — целевое состояние: не персистить в открытом виде в localStorage (`partialize` в zustand `persist`, либо Electron `safeStorage` при запуске в Electron), см. [[decisions#ADR-010]].
- При обнаружении секрета в репозитории — не печатать значение, только путь/тип/детектор.

## Границы доверия и валидация
- Внешний ввод пересекает границу доверия в трёх местах: HTTP-запросы к `api/index.ts` (auth + `/api/projects`), тело запроса к AI-провайдерам (промпты пользователя), локальный вызов CLI-агентов из `electron/main.ts` (аргументы командной строки).
- `Origin`-заголовок запроса — граница доверия для CORS и CSRF-защиты better-auth; допустимые origin'ы — только явный allowlist, никогда отражение входящего заголовка и никогда wildcard `'*'` (см. [[decisions#ADR-005]], [[decisions#ADR-006]]).

## Идентификация, доступ и привилегии
- Аутентификация — better-auth, cookie-based сессии.
- Любой HTTP-маршрут, читающий или пишущий данные, привязанные к пользователю (`projects` и производные), обязан проверять сессию (`auth.api.getSession()`) и фильтровать/проставлять `userId` — не полагаться на то, что маршрут "пока не задеплоен" (см. [[decisions#ADR-003]]).
- Electron: `contextIsolation`/`nodeIntegration` — включены и обязательны для любого нового `BrowserWindow`; `webSecurity` не отключается без явно задокументированной причины (см. [[decisions#ADR-010]]).

## Чувствительные данные, наблюдаемость и транспорт
- Ошибки, отдаваемые HTTP-клиенту, не должны включать `stack`/внутренние сообщения исключений — только нейтральный текст; полные детали — в серверный лог (см. [[decisions#ADR-010]]).
- CORS: `Access-Control-Allow-Credentials: true` — только вместе с проверенным против allowlist `Origin`, никогда с отражённым/wildcard-значением.

## Зависимости и цепочка поставок
- Целевое состояние: CI (`.github/workflows/release.yml`) пиннит сторонние GitHub Actions по commit SHA, не по мутируемому тегу. Сегодня `actions/checkout@v4`/`actions/setup-node@v4` заданы тегом — низкоприоритетный пункт долга, см. [[decisions#ADR-010]], [[migration_backlog#MB-012]].
- Проверка уязвимостей зависимостей через package-manager/сетевой advisory-источник не выполнялась в рамках этого аудита (офлайн-профиль, без сетевого доступа) — при следующем аудите с сетевым доступом стоит явно включить эту проверку.

## Сбои и реакция
- При отсутствии обязательного секрета (`BETTER_AUTH_SECRET`) — процесс не должен стартовать с небезопасным дефолтом; явный сбой предпочтительнее тихой уязвимости.
- Небезопасные значения по умолчанию (`webSecurity: false`, wildcard CORS/origin) — не вводятся без явного ADR, фиксирующего причину.
